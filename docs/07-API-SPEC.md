# 07 — API Specification

## 1. Principles

- REST over JSON, FastAPI, all routes under **`/api/v1`**.
- **OpenAPI is the contract.** The TypeScript client is generated from it; enum
  values come from `analytical_core.enums` via `docs/12`. No hand-kept types.
- Routers are thin: validate → service → serialise. No analysis / scoring math
  in the API layer.
- **Read endpoints serve from the `current_*` projections** (`docs/03` §5.5);
  historical endpoints hit `signal_scores` / `analysis_results` (resolves H8).
- Read-heavy. V1 writes: config edits, instrument-tracking toggles, manual run
  triggers.
- **This API exposes analytical decision-support only.** No endpoint returns or
  accepts BUY/SELL/execution instructions. Score labels are analytical
  (`STRONG_BEARISH … STRONG_BULLISH`).

## 2. Auth seam (single-user V1 — resolves H12)

- Global dependency `get_current_principal`; V1 returns a fixed `owner`
  principal, optionally requiring `Authorization: Bearer <LOCAL_API_TOKEN>` when
  that env var is set.
- V1 has **global** config and a **global** tracked universe. There are **no**
  per-user resources (no `watchlists`, no `scoring_profiles`) and no endpoints
  for them. The earlier "owner-scoped resources" language is removed.
- Future real auth = swap the dependency + add `/api/v1/auth/*` + user-scoped
  tables. Domain endpoints keep their signatures.

## 3. Conventions

- **Errors:** `application/problem+json` (RFC 7807):
  `{ type, title, status, detail, instance, errors? }`. Field validation → 422
  with a field-keyed `errors` object.
- **Not-applicable analyses are not errors.** Requesting OI for an INDEX returns
  a normal `200` analysis item with `status = NOT_APPLICABLE` (not a 4xx).
- **Pagination:** `?limit=` (default 50, max 500) + `?offset=`. List responses:
  `{ items, total, limit, offset, next_cursor(null) }`.
- **Filtering/sorting:** explicit params per endpoint; unknown params → 422.
- **Time:** all timestamps ISO-8601 UTC (`Z`), **bar-open**. Requests may pass
  IST offsets; responses are always UTC.
- **Scope in analysis payloads:** every analysis item carries `scope`
  (`PER_TIMEFRAME / SESSION / SNAPSHOT`) and exactly one of `timeframe` /
  `session_date` / `snapshot_ts` (resolves C1).
- **Versioning:** breaking change ⇒ `/api/v2`. Additive fields are non-breaking.
- **Idempotency:** `POST /runs` accepts an `Idempotency-Key` header. A repeat of
  the same key within `idempotency_window_seconds` (default 600) replays the
  original run — `200` + the run body, no new cycle — instead of `202`. The key
  is stored on the run's `config_snapshot.idempotency_key`.

## 5. Payload notes

- Analysis `result` payloads are exactly the engine contract (`docs/05` §14),
  validated by shared Pydantic models on write and read.
- Unknown numeric fields are `null`, never `0` sentinels (`rvol`, `oi_change`,
  `bandwidth_percentile`, `slope`, …), each with a sibling `status` where
  relevant.
- `delta_vs_previous` is computed server-side (worker, into
  `current_signal_scores`) from the prior run's score for the same key.
- Every analysis item includes provenance: `algo_version`, `params_id`,
  `params_hash`, `as_of_ts`, `coverage_ratio`, `carried`.
- `status = NOT_APPLICABLE` items include a `reason` and are rendered as
  collapsed/greyed panels by the frontend, not errors.
- `order_block` (`docs/05` §9a; INDEX / FUTURE PER_TIMEFRAME) `values` =
  `{ bias (BULLISH|BEARISH|NEUTRAL), zone_state (OUTSIDE|IN_BULLISH|IN_BEARISH),
  price, atr, n_active_bullish, n_active_bearish, nearest_bullish,
  nearest_bearish, zones: [{ side, low, high, mid, formed_ts, bos_ts, age_bars,
  mitigated, mitigated_ts, distance_pct }] }` — descriptive, no BUY/SELL, no
  entry / target / stop.
- `candles` (`docs/05` §9b; INDEX / FUTURE PER_TIMEFRAME) `values` =
  `{ bias (BULLISH|BEARISH|NEUTRAL), last_pattern (CandlePattern|null),
  last_bias, last_strength (WEAK|MODERATE|STRONG|null), last_bars_ago,
  on_last_bar (bool — the frontend "alert" highlight), n_bullish, n_bearish,
  bars_scanned, patterns: [{ pattern, bias, strength, trend_context
  (UPTREND|DOWNTREND|SIDEWAYS), bar_ts, bars_ago, open, high, low, close }] }` —
  descriptive labels only, no BUY/SELL, no entry / target / stop.

## 6. Non-goals (V1)

- No websockets / SSE (frontend polls; a later additive endpoint).
- No bulk export, no GraphQL.
- No per-endpoint rate limiting (single user); a middleware hook point exists.
- No write access to market data.
- No order/execution endpoints — now or as a V1 extension.
